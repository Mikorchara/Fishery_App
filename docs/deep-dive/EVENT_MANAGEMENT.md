# 事件周期、确认、人工结束与清理

这是当前事件合同，涵盖事件生命周期、等级、人工结束和删除。SQLite 仍为 v2。水质诊断阈值和模拟视觉三窗恢复沿用原规则。

## 一个风险周期一行

同设备、同指标、同风险类型及规则身份下，稳定risk_family.episode_id关联不同等级code，保留原始事件ID、证据和变化轨迹。页面按稳定周期汇总，不同设备/风险/规则版本不合并；旧legacy-*推断身份不强行归族。

活动摘要展示当前可靠等级与最近观测；已恢复展示首次/恢复时间和历史最高等级，读数标“异常时读数”。新严重等级出现不证明旧等级已经恢复；降级不是恢复。首页当前异常与最近事件使用同一周期投影。

## 观测状态与人工状态分开

| 状态 | 依据 |
|---|---|
| 异常中 | 可靠HIT，或仍在恢复观察中 |
| 状态待核实 | 缺测、过期、离线、证据不足、旧规则身份不可靠 |
| 已恢复 | 规则有可靠CLEAR并满足本规则恢复条件 |
| 已人工结束 | 人工结束旧提醒；原Monitoring状态和证据仍保留 |
| 已确认/未确认 | 人员知晓当前周期当前等级，不代表风险消退 |

模拟视觉异常需连续三个完整、可靠、新鲜的 CLEAR 窗口恢复。缺测、离线、部分无信号覆盖不算 CLEAR。Session 变化打断连续证明。消退只代表未再检出该规则信号，不代表疾病治愈。读时过期投影不回写历史、不伪造恢复时间。

不同数据来源和事件类型的判定：

| 来源 | 异常如何结束 | 页面怎样显示 |
|---|---|---|
| 模拟水质 | 新观测可用、规则CLEAR，且同指标没有其他等级异常仍命中 | 周期“已恢复”，保留恢复时间和历史最高等级 |
| 模拟视觉 | 连续3个可靠、新鲜且连续的CLEAR窗口 | 前两窗恢复观察，满足第三窗后“已恢复” |
| 设备外观报告 | 有明确外观观测和正数目标的新版窗口更新本轮事件。过期或缺失有效外观观测时转为待核实 | “异常中”或“状态待核实” |
| 设备行为结果 | 按行为文件版本的独立时间和编号记录异常视频。后续异常版本登记为另一条事件 | 最新异常版本“待核查”，更早版本保留历史证据 |
| 设备报告更新中断 | 连续收到 3 个有效新版窗口后，距最后一个窗口结束满 180 秒仍未更新。下一份按时到达的新鲜有效窗口结束本次中断 | “报告未更新”或“上报已恢复” |

“已恢复”是监测规则结论，历史记录仍保留；“已确认”只是人已知晓；“已人工结束”是结束本次关注提醒。设备报告的“上报已恢复”只说明有效报告重新到达，不是外观或行为异常已消退。新版设备事件与原视觉恢复规则的区别见[设备视觉页改版与数据清单](../development/DEVICE_REPORT_REDESIGN.md)。

旧格式报告仍可触发原设备视觉信号，留存分包仍可回看。2026-11-09 的现场联调验证了新版外观事件更新以及旧行为版本不重复登记。新的行为事件和报告中断恢复使用合成输入验证。

详情文案按结构化原因区分“已升级为…”、“同指标等级已变化”、“恢复状态待确认”、“监测数据中断”、“规则条件已消退”；不能靠标题字符串猜原因。

## ACK

只在当前有效周期/等级接受“确认已知晓”，由操作者确认。本机未登录，只记录本机操作，不伪造认证工作人员。

ACK绑定稳定周期、等级序号与grade_token/version和人工revision。同等级HIT保留；升级或等级版本变化重新待确认，旧操作保留。消退后不能新ACK；复发是新周期，不能继承旧确认。失联本身不清除历史确认。

SQLite独立event_handling、event_actions、event_handling_members保存引用和操作历史；幂等请求ID防重复，事务校验周期/等级/revision。legacy推断身份默认只读。

## 失联风险人工结束

只有因过期、离线、缺测或无效导致待核实，且同周期没有可靠ACTIVE或恢复观察的风险可操作。详情填写1–200字原因并确认；数据质量告警仍可靠命中时不属此范围。

操作追加manual_ends证据与本机来源，不改Monitoring ACTIVE/INDETERMINATE/RESOLVED、不填规则恢复时间、不删alerts/ACK/观测。稳定周期处理整周期，推断旧记录只处理所选原始ID。新可靠HIT、新等级或规则身份变化会重新提醒。

相同请求幂等、人工revision排序、预览和提交CAS、事务重读观测；最多50次，不静默裁审计。不含Snooze、派单或通用Close工作流。

## 时间与筛选

事件列表支持关键词、等级、状态和最近5/10/30/60分钟/全部组合筛选。时间按风险活动区间是否与所选区间相交：开始早但仍持续的事件不会被误排除，已结束需恢复时间与区间相交。查询从服务端完整留存事件投影成周期后筛选/分页，不只合并前端已加载一页。

首页当前异常独立于历史时间筛选。无活动异常但可靠观测不足时不显示“全部正常”。保留完整原始记录、来源和原时间，不回算历史。

## AI 问答的事件查询权限

对明确询问「现在有什么活动事件」的请求，Web 从本轮实际启用的能力和冻结的工具授权判断原因。当前事件工具可能在当前模式下不可用、在本次服务启动时未启用，或在本轮未获授权。现代 QQ Agent 按成员授权和实例策略的实际交集判断。提示由服务端生成，用户文本和旧对话无法授予工具权限。

只问事件时，答复直接说明无法核实的原因。明确同时查询当前溶解氧、pH 或水温中的单项读数时，若当前水质工具仍获授权，使用 `get_current_water_quality` 的本轮回执回答该项。只有对应指标有效、观测新鲜及设备在线时才展示数值，并标明模拟来源、设备和北京时间。缺少观测或授权时说明限制。流式网页在核对完成后展示正文。

当前事件工具已获授权时，查询结果继续记录自己的来源回执。`NO_DATA` 表示缺少可供核实的观测，`NO_MATCH` 表示已查询范围内未找到匹配事件。显式历史专用试验继续要求历史来源回执。此次权限提示的识别范围覆盖明确当前事件问法，以及与一个明确当前水质读数并问的两句问法。[原能力提示 v2 的实验](<D:/CodexProject/LLM_Lab/docs/records/2026-11-23-fishery-event-capability-notice.md:47>)

## 事件查询的观测范围

事件查询使用 `management-active-events@3`。返回事件记录的同时，`observation_scope` 按实际授权结果列出来源、设备、通道、观测时间和范围状态。模拟水质、模拟视觉、板端报告各自评估。当前查询未绑定某个板端时，结果不为该板端补缺测结论。第三版在相同的观测范围之上，将结果中的评估、观测、事件、行为版本和报告窗口时刻写为带 `+08:00` 的北京时间。模型可直接引用这些钟点。

| 范围状态 | 答复依据 |
| --- | --- |
| `ASSESSED` | 模拟通道有有效、新鲜、在线的观测。无匹配的结论可限定在该来源和通道内。 |
| `PARTIAL` | 模拟通道观测覆盖不完整。说明无法全面核实。 |
| `MISSING`、`STALE`、`UNUSABLE` | 分别说明缺少观测、已过期、无法用于当前判断。板端的过期时间取报告窗口结束。 |
| `REPORT_ONLY` | 有较新的板端报告。外观和行为的完整观测范围仍未知，各项阳性信号以实际事件记录中的证据为准。 |

`NO_MATCH` 只说明查询没有匹配记录，结果里带时间的观测也可能已过期。只有 `ASSESSED` 通道可以用来写当前有效观测范围内的无匹配结论。`NO_DATA` 表示本次查询范围内没有观测。报告中断仍是报告更新问题，连接状态需要独立证据。

首轮工具简介用于选择工具。查完后才加入事件结果说明，其中要求「本次在〔有效观测的实际来源和通道〕范围内未查到匹配事件」。结论句本身要写出范围，视觉缺测要单独说明。查到事件时区分活动风险、待核实和行为待复核，按所问证据使用实际来源及观测时间。模型仍可在组合问题里查询获准的第二个工具。

新对话的明确独立事件问题，在只取得一份有效事件回执且没有匹配事件时，由程序生成最终正文。若明确同时询问一个当前溶解氧、pH 或水温读数，且两项工具均已授权，要求两项查询均有本轮回执。事件无匹配时由程序按各自回执组织事件范围和读数。读数必须对应本轮有效、新鲜观测，时间由程序转为北京时间。模型照常选择工具并完成请求。带历史的追问、其他组合问题和有匹配事件的答复由模型按新说明生成。QQ 来源栏保留来源、报告窗口和时间，将无匹配结论留在正文。

## 永久删除与彻底清空

在本机网页的“事件记录”中提供两类操作：普通清理仅删符合条件的已结束历史；明确的“删除此轮事件／清空全部事件记录”可以彻底处理活动、待核实、旧记录及人工留痕，避免产生无处处理的残留。

### 任意事件和全部清空

- **删除此轮事件**：删除选中页面行对应的整轮风险，包括不同等级原始记录及其ACK、人工结束历史；不能可靠归族的旧记录按单条处理。
- **清空全部事件记录**：范围为当前实例、全部设备、全部时间，不受筛选和分页影响。包括活动、恢复观察、待核实、已恢复、ACK和人工结束记录。
- 点击后先列出实际影响的事件、ACK和人工结束数量，确认一次再提交。操作不可在应用内撤销；取消不删除。
- 只清事件及关联人工记录/活动事件引用；不清水质当前观测、历史、批次、原始设备报告、聊天、QQ通知发送日志、知识库或设置。设备报告处理游标保留，旧报文不会因清空而重新导入。
- **持续的异常在下一份新观测到达后仍可生成新事件。** 清空记录不停止监测、不把水质改成正常，也不自动关闭QQ。若希望演示时保持空列表，先切换为正常场景或停止新的上报。
- 清空后，视频页的原始设备报告仍可回看；它们不是残留事件。事件列表和首页事件概况刷新后以服务端结果为准。
- 新scope=`reset_cycle`/`reset_all`仅供原本机维护API使用，保留预览revision、事务、外键及并发冲突检查；不是AI工具。普通清理的保护规则不因此放宽。

### 普通删除已结束周期

身份可靠且所有成员均RESOLVED、closed、有有效恢复时间，页面提供“删除已结束周期”。确认框列出全部等级原始记录和ACK历史数量；确认一次后同事务全部删除，避免只删一个等级而同一行还在。

新显式scope=cycle复用原ACK周期事务；旧single与ack_cycle保持兼容。无法可靠归族的旧已结束记录按原单条规则处理，不冒充可靠恢复。

### 普通批量清理

“清理全部已结束事件”作用于全部设备/全部时间的可删除记录，**忽略当前筛选和分页**；预览数量、二次确认。批量不隐式删除ACK审计。取消不提交。

### 普通清理的保护与事务

- 活动、恢复观察、状态待核实拒绝；人工结束审计及必要原始记录继续保留，即使后来恢复也不参与本次开放的删除。
- 预览revision绑定成员、payload和ACK；提交BEGIN IMMEDIATE内重查状态、成员、告警、外部superseded_by与审计引用，不信任前端数量。
- 外部引用、成员不完整、并发变化或SQL失败拒绝；中途失败整笔回滚，不靠级联删除绕过约束。重复删除已不存在ID返回明确错误，不复活记录或自动重试。
- 只删除选中周期及明确批准的ACK；不删水质history/current/batches、Knowledge、Settings、Policy、Trace和其他周期。

永久删除在应用内无法撤销。自动留存默认保留最近300条未受保护历史；活动引用、ACK或人工结束记录可能额外保留，因此总数可能超过300。自动裁剪不是清库功能；需要彻底清理时使用上述明确维护入口。升级后重启Web、Ctrl+F5获取新前端。
