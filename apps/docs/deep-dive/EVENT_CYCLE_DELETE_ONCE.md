# 已结束事件一次删除修复

## 原因

事件列表按风险周期合并展示，但未人工确认的周期，详情原先仍使用“删除此原始记录”。例如低氧从“偏低”升级到“严重”，底层保存两条原始事件，列表只显示一行。第一次删除只删除其中一条，另一条继续投影为同一周期；等级轨迹还保留历史最高等级，因此标题也可能仍是“溶解氧低”，看起来像同一条记录没有删掉。

已用新建合成 SQLite 复现：删除前为一行、两条原始记录；旧单条删除返回成功后仍为一行、一条原始记录，周期键和标题相同。不是删除后自动复活，也不是必须重复发送同一请求。

## 现在的操作

对身份可靠且已经结束的风险周期，列表和详情统一提供 **“删除已结束周期”**。确认框显示原始记录数量，以及是否同时删除人工确认历史。用户确认一次后，服务器在同一个事务中删除整个周期的各等级记录及其关联 ACK 历史。

这是永久删除，应用内不能撤销。取消确认不会删除任何数据。完成后刷新列表、首页和计数；之后的正常观测不会重新生成已删除的历史周期。

升级后重新启动 Web，并在浏览器按 `Ctrl+F5` 读取新版页面。QQ 使用的共享源码指纹随 Repository 改动而更新，下次启动需要新的本次审批；2048 输出 Token、5 Turn 和 8.06 元预算不变。

## 安全边界

- 新增显式删除范围 `cycle`，复用原周期删除事务；旧 `single`、`ack_cycle` 和批量清理范围保持兼容。批量清理仍不隐式删除 ACK 审计。
- 只按稳定周期身份关联，同时绑定设备、通道和规则身份；不依靠标题、严重程度或相近时间猜测合并。无法可靠归族的旧记录继续独立处理。
- 周期内全部原始记录都必须是 `RESOLVED`、`closed`，并具有有效恢复时间；活动、恢复观察和状态待核实不能删除。人工结束留痕保护继续保留。
- 预览返回 revision，提交时在 `BEGIN IMMEDIATE` 中重新核对成员、状态、告警和审计引用。预览后记录变化则拒绝，不自动重试。
- 外部周期引用、告警引用、ACK 关联不完整或存储错误都安全拒绝；删除中途出错时连同 ACK 一起回滚。不使用级联删除绕过保护。
- 不修改水质观测、历史、采样批次、规则、阈值、恢复判定或 SQLite Schema。没有替用户删除实际记录。
