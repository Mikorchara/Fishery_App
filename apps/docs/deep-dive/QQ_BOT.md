# QQ Bot：配置、运行与排错

QQ的详细机制只维护在本页。首次配置按根目录[开始使用](../../../开始使用.md#6-可选开启-qq-机器人)，日常入口见[BUILD_RUN](../BUILD_RUN.md)，停止和备份见[运行维护](OPERATIONS.md)。

## 当前实现

网页“系统设置 → QQ机器人”集中管理AppID、群和成员OpenID、启用开关、每次模型请求最大输出Token、QQ AppSecret保存、接收人网页配对及事件提醒开关。未启用网页AI、尚未配置QQ时也能打开。实例、设备和配置目录由服务端固定，浏览器不能提交文件路径。

QQ仍是独立进程：官方Gateway → 程序固定分支/Hybrid路由 → Coordinator/Scheduler → ManagementAssistantService → 原AssistantService/ToolCallingService → Qwen或授权只读Tool。与Web复用Agent实现，分别装配，不共享浏览器权限或运行中的Service对象。Web和Simulator不依赖Bot。

网页新保存的配置采用独立 `management-qq-web-agent-run@1`（request schema 3）：当前进程人工批准一次，直到人工停止、撤权或严重故障；不按整次运行时长、累计AI轮数或累计费用停止。普通自然语言可能持续产生费用，Token不是云账单硬上限。

## 网页设置与生效

- AppID是应用ID；群和成员须使用平台OpenID，不是普通QQ号码、群号或昵称。一个明确群、一个实例和设备，最多4名明确成员。
- 默认关闭QQ及AI。填写和保存不会联网、测试密钥、启动进程或发送消息；Bot启动仍须核对并批准本次运行。
- Token默认2048，范围1–4096，控制**每次模型HTTP请求最大输出Token**。Agent每轮最多3次模型请求，不能把它解释为整个Turn的合计上限。
- 保存后重启Bot生效。启动冻结Token、身份、设备、Policy和Scope；配置改变使旧授权失效，不在执行中修改共享Service。保存不是自动续批。
- 非敏感设置在同一实例的 `qq-bot-settings.json`；Bot配置在 `outputs/qq-m3-real-config`。没有新增聊天或业务数据库。已有配置须由操作者在页面确认保存，不自动修改实际配置。
- AppSecret在隐藏输入框单独提交，沿用原私有CredentialStore，不存项目JSON或浏览器存储、不回显。读取设置不会访问密钥，页面“未检查”不表示密钥缺失。DashScope Key仍在原API密钥页设置。
- 事件通知只能发给同App验证的接收人，页面不接受任意文件路径；首次接收人可直接在本页配对，步骤如下。

## 自然回答和可信来源

固定查询、帮助、工具能力、常见问候和清空会话由程序处理，不产生模型请求。其他授权自然语言进入现有Agent；不靠不断增加业务关键词分类。只处理平台认证的群@事件，伪造@文本不能触发模型。

当前 Prompt 为 `QQ_MANAGEMENT_WEB_AGENT@3`，复用 Web 多轮系统指令、原 Agent、History Projection 和 ToolCallingService。模型可查询当前水质、10/30/60 分钟历史水质、项目知识库、实验水质评分和当前事件。五项工具均只读，实际范围由 Bot Policy、群成员权限与本次启动审批共同限定。

不要求General/Water JSON，不设旧General 600字符发布限制，不将调用Tool后的回答统一替换成水质模板。最终单条消息仍有1500字符的整体长度预算，包含来源说明；超长会明确提示缩小问题，不截断来源后假装完整、不自动重推理。General通常1次模型请求0Tool；最多2次只读Tool、2轮工具迭代、3次模型请求，沿用原Web多轮执行循环。

系统按本轮实际Tool步骤和Receipt附来源，不把不同来源拼成一份水质事实：当前/评分保留SIMULATOR、观测时间、质量、新鲜度、连接状态与规则HIT；历史标记时间窗口及“不是当前”；知识标记实际背景证据与“不是现场事实或确诊”；无Tool回答说明未读取现场或项目资料。stale/offline/missing不成为当前正常，旧读数不新增当前HIT，没有HIT也不能证明无风险。

模型正文保留自然表达，只有有限的格式/长度与明确冒充查询或操作完成检查；一般温度数字、概念解释和“不能确诊”等否定说明不因关键词误拦。检查不是通用逐句事实验证器；Tool Receipt证明查询发生，不证明模型每一句都正确。不同失败给出不同提示。新功能没有改善Qwen网络速度或把模型回答变成专业保证。

## 首次在网页绑定事件接收人

1. 正常停止Bot，保留Web。先保存QQ身份和AppSecret，确认手机QQ已经添加同一应用的机器人好友。
   一次只绑定一名事件接收人；给新组员配对会替换当前通知目标，并默认关闭通知。群里提问的成员不需要逐一配对。
2. 在“系统设置 → QQ机器人”的接收人配对区域，勾选明确的QQ联网确认，再点“开始配对”。这一步才会连接QQ；不调用Qwen、不读取Monitoring或知识库。普通页面读取、保存和Check均不联网、不读取密钥。
3. 页面显示一次性 `/私聊验证 …`，在手机QQ与机器人的私聊中原样发送；不要转发。配对最多180秒，普通群消息和旧口令无效。
4. 页面识别后显示接收人摘要；核对本人，再明确批准一次主动测试通知。未知送达不自动重发，也不自动绑定成功。
5. 平台接受测试后，检查QQ客户端是否实际显示。页面绑定同App证明，但默认关闭正式事件提醒；重新读取设置，勾选“启用已验证接收人的事件通知”并保存。
6. 重新启动Bot，核对本进程批准摘要包含正确接收人和事件披露范围后批准；产生新异常/升级/可靠消退时再验收。配对成功不等于通知已启用，也不授予AI或数据库权限。

可取消、超时后重新开始新的配对；同一Bot运行中或另一配对占有应用时拒绝启动，避免抢占Gateway。Web停止会有界取消配对并释放资源；清理未确认则拒绝再启动。页面不保存原始私聊正文或密钥；本机证明含必要的私有接收人身份，不要上传Git或共享outputs。

## 会话、执行与交付

ConversationStore保存在RAM，按App、群、成员、实例、设备、授权版本和Scope隔离。最多6个成功Turn，空闲15分钟过期，总64会话、每会话24KiB、全局1MiB；重启不恢复聊天。历史只帮助理解话题：新的当前水质问题仍须查询本轮Tool，旧水质数值不成为当前事实。混合历史明确标记旧回答及来源时间，仍经不可信历史投影进入原Agent，不生成新的Receipt或授权。

新Web-Agent模式每个AI Turn继续限定90秒、最多3次模型请求、2次只读Tool、零自动重试；一个AI worker和两个等待位置。BUSY、重复消息、未授权成员不能启动模型。QQ原消息回复窗口仍有效，与整次Bot在线时长不同。

每轮有独立Service、Session、RequestHandle和最长90秒的内部TurnLease。当前进程的RunConsent及OS所有权不能从聊天或JSON批准字段伪造。写前审计、检查点失败会停止AI；不恢复旧任务、不重放旧消息。持续模式保留累计统计与磁盘逐Turn记录，RAM只保留近期摘要、活动对象和有界会话，不全程堆积模型/会话对象。

沿用SDK资源租约，确认Client/Stream关闭和请求线程退出。取消请求、本地I/O中断、线程退出及远端停止计算/计费是不同状态；不合作线程仍可能无法强制结束。清理未确认则隔离本Bot进程，不成功Commit或继续请求，不清零门禁重试。独立进程不把隔离状态传给Web。

每个原消息只有一个被动回复Owner。发送前复核身份、Scope、SDK状态和消息期限；未知送达不重发或重推理。只有Backend/Source/Commit成功、SDK安全关闭、QQ API明确接受、发送文本哈希及会话revision匹配后才提交成功历史。失败、取消、撤权、未知交付不追加成功历史；`/清空会话`只清当前成员记忆。API接受与客户端实际显示分别记录。

## 旧有界配置兼容

旧 `management-qq-continuous-run@1`（schema 2、仅当前水质）、`management-qq-hybrid-process-run@1`、FAST和双轮合同保持原义，旧JSON解释和有限额度仍可使用。旧 `prepare-demo` 仍是独立合成测试入口；不把旧批准、used标记或Provider回执改成无限许可。旧默认1800秒、5Turn、8.06元预留、每请求2048，仅作兼容说明。

网页明确保存已有配置后生成独立持续合同与当前源码Scope；保留旧配置备份，不改历史批准。Scope准备记录保持candidate、qualification为空；实际联网需要本进程的新人工批准，不能仅修改candidate或can_deliver标记开启。

## 事件通知与设备报告

事件私聊通知默认关闭。启用须同App受控好友接收人及本次明确批准；只发授权设备事件，不由QQ号码或昵称推断身份。首次按本页网页配对，不需要从Prototype迁移证明；默认不启用不影响群问答。

SIMULATOR新异常、升级和可靠消退各提醒一次；连续同级HIT和ACK不刷屏，不重放启动前历史。发送前持久化声明，失败、未知及重启不自动重发。每日100次、10秒最多1条是通知防刷屏规则，与AI会话轮数无关。私聊成功不代表群主动权限。

设备联调绑定报告目录和设备 ID 后，Web 将有效的设备事件同步到 Monitoring。QQ 沿用已批准的私聊通道提醒新版外观异常（E1），也兼容旧格式视觉异常。行为异常（E2）和报告更新中断（E3）只在网页展示。设备报告与 AI 水质工具分属独立的数据来源。操作见[设备连接步骤](../DEVICE_INTERFACE_QUICK.md)。

## 排错与验证

| 状态 | 含义 |
|---|---|
| `AI_ADMITTED` | 仅准入，继续看 `AI_TASK_FINISHED` |
| `INVALID_TOOL_ARGUMENTS` | 模型参数不符合对应工具Definition（当前/评分为 `{}`，历史为时间窗口，知识为query），不放宽设备绑定或自动补跑 |
| `MODEL_RESPONSE_TRUNCATED` / `ASSISTANT_RESPONSE_TRUNCATED` | 达到本轮输出上限，不提交残缺成功历史 |
| `RUN_TURN_LIMIT` / `RUN_BUDGET_EXHAUSTED` / `INVALID_RUN_DURATION` | 旧有限配置限制；在网页确认保存为新持续模式 |
| `QQ_REPLY_API_ACCEPTED` / `QQ_EVENT_NOTICE_API_ACCEPTED` | 平台接受，客户端显示仍需独立确认 |
| `DELIVERY_UNKNOWN` | 不重发、不重推理、不追加成功历史 |
| `MANAGEMENT_SCOPE_REVIEW_REQUIRED` | 本机配置记录的 Scope 与当前实现不一致。按下节恢复启动 |
| SDK资源隔离或必要检查点失败 | 停止新AI，保留报告并正常停止，不重置门禁 |
| `MANAGEMENT_BOT_REPORT_SAVED` | 最终报告落盘，分别核对Backend、SDK、交付与History |

`-Check`不读取密钥、打开Monitoring数据库或联网，不能证明平台权限、真实密钥及网络可达性。页面读取与保存也不会联网；只有显式批准的配对开始/测试和Bot运行才联网。Fake/Mock证明执行与故障边界，不能替代真实Qwen的工具选择、自然语言质量及长期运行验收。

真实验收应分别记录一般概念/季节问题/当前水质/话题切换/连续追问/缺测过期/权限拒绝的实际Tool次数、模型请求、Token、耗时、SDK和交付；不能把Backend完成或API接受当作回答质量正确或客户端自动显示确认。

### 代码指纹与恢复启动

Bot 启动前会对选定的实现文件计算 SHA-256，再把这些摘要与 Prompt、工具、执行限制等一起纳入 Scope。程序会比对当前算出的 Scope、本机配置的 `scope.json` 和启动请求里的 Scope 摘要。设备事件与通知代码在检查范围内，单纯修改网页文案不会改变它。

如果版本升级后遇到 `MANAGEMENT_SCOPE_REVIEW_REQUIRED`，由维护者核对更新涉及的工具、权限和通知规则。然后按以下步骤恢复：

1. 用两终端入口打开同一日常实例，在「系统设置 → QQ 机器人」核对现有 App、群、成员、AI 和事件通知开关。
2. 点击「保存 QQ 设置」。正常保存会生成当前版本的配置和指纹，并备份旧配置目录。旧模式或自定义权限的配置应先核对生成后的工具与授权范围。
3. 停止两终端，再执行 QQ 入口的 `-Check` 或启动预检。设备联调时，8780 接收器可继续运行。检查通过后启动 QQ 版，并在 Bot 窗口批准这次运行。

使用纯网页或模拟器时无需 QQ Scope。正式 QQ 入口保留指纹检查，让源码变化后的新运行继续接受人工核对和批准。

### QQ 查询当前事件

沿用原 QQ 启动入口和审批。在已批准的群里 @机器人，问「请问现在发生什么事件了吗？」即可。完整模拟模式查询已绑定的模拟设备。设备联调模式在启动审批中列出已绑定的开发板及摘要披露范围，同意后才可查询该板的事件。旧配置升级时在网页重新保存一次，工具随现有配置生成。主动私聊提醒仍走接收人配对和原通知授权。
